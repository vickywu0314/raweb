# raweb 后端接口依赖清单

状态：已核对（2026-10-07，对照 raapi `2f896da` 的 [API.md](../../raapi/docs/API.md)）

raweb 通过 `js/common.js` 的 `apiPost` / `apiPostJson`（`API_BASE = http://localhost:8065`）调用 raapi，共依赖 **13 个接口**，全部 POST。统一返回 `DataResult{success, code, message, data}`（列表类另有 `dataList`/`page`，CSV 导出除外）。

## 二、核对结论

13 个接口在 API.md 中全部有对应章节，参数、枚举、响应字段逐一核对一致；两处结构性调用（`visitsCsv` 直连下载、`updateVisit` 的 modules 键控对象）均符合文档。未发现契约性偏差。

## 三、发现的问题与缺口

### 前端实现问题（建议修复，不影响契约）

1. **转入分支性别硬编码**：`patient-create.js:70` 转入（`transfer:true`）时 `basic.gender` 写死 `1`。API.md 明确转入不改基本信息，故无功能影响，但属粗糙代码，建议传 `x` 中已知值或省略。
2. **转入确认疑似重复触发**：`patient-create.js:62` `handleExisting()` 在绑定「转到我名下」按钮后又立即调用 `transfer()`，弹窗会在查重返回后未经点击直接出现。

### 接口缺口（前端依赖但后端尚未提供）

| 缺口 | 现状 | 影响页面 |
|---|---|---|
| 新增随访保存 | `visit-create.js:41-45` 保存被前端阻断（接口开发中）；API.md 无对应章节 | visit-create |
| 编辑患者档案（注释称「接口 PT11」） | `patient-edit.js` 仍走演示 `patientById` + `patchPatient`（localStorage），**未接后端**；API.md 也无编辑档案章节 | patient-edit |
| 登录/会话 | 演示版 localStorage 会话，无 auth 接口 | 全部页面（boot.js 守卫） |

### 双数据源口径（迁移中，注意混用风险）

- **已接 raapi**：患者列表、患者详情、访视详情/编辑、项目总览、建档。
- **仍用演示数据**：随访管理、数据看板、数据质控、AI 分析各页，以及**编辑档案页（patient-edit，本次核对补充发现）**。这些页面从 `data.js`/`common.js` 演示数组读写，与 raapi 数据互不可见。

## 四、维护约定

- 后端每加一个接口，按 API.md 末节约定在 API.md 补章节，并在本清单「接口总表」补一行（调用位置需精确到 `文件:行号`）。
- 前端新调用必须走 `apiPost`/`apiPostJson`（文件下载类除外，参照 `downloadVisitsCsv`）。
- 页面切换 raapi 口径时，同步更新本清单「双数据源口径」一节。
- 不启动 raapi 也想跑前端时，用 `npm run mock`（见 [mock/README.md](../mock/README.md)），13 个接口全部有 mock 实现。
